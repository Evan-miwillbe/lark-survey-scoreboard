# 评分数据 → 分析报告 — Prompt 设计说明

## 设计目标

将评分数据自动转化为有洞察力的分析报告，不只是复述数字，而是给出可执行的判断和建议。

## 分析层次

报告生成分为三层，逐层递进：

### Layer 1: 描述层（What）

纯数据呈现，不加判断：
- 参与人数、完成率
- 各维度均分排名
- 单题最高/最低分

### Layer 2: 诊断层（So What）

基于数据给出判断：
- 哪些维度是亮点（>=8分）
- 哪些维度需关注（<6分）
- 分数分布是否集中（标准差）
- 是否存在"高期望低分"的落差

### Layer 3: 建议层（Now What）

基于诊断给出行动建议：
- 低分维度的可能改进方向
- 高分维度的保持策略
- 下次评估的关注点

## 报告结构

```markdown
# [标题] — AI分析报告

## 整体概览（数字仪表盘）
## 维度排名（从高到低）
## 亮点（做得好的）
## 需关注（需改进的）
## 单题详情（Top3 + Bottom3）
## 改进建议（具体可执行）
```

## 设计决策

### 为什么不用 AI 大模型生成报告正文？

当前实现用代码直接分析数据+生成报告，而非把数据丢给大模型让它写。原因：

1. **确定性**：数字分析必须精确，大模型可能算错均分
2. **速度**：代码分析毫秒级，不需要等API调用
3. **离线可用**：不依赖外部AI服务
4. **可验证**：逻辑清晰，输出可复现

### 未来可扩展

如果需要更深层的AI洞察（如"为什么沟通维度分低"），可以在代码分析完成后，把结构化数据交给大模型做二次解读。但基础报告不依赖AI。

## 颜色/评级标准

| 分数范围 | 评级 | 含义 |
|----------|------|------|
| 8.0-10.0 | 优秀 | 明确亮点，保持现有做法 |
| 6.0-7.9 | 良好 | 达标，有提升空间 |
| 4.0-5.9 | 待改进 | 需要关注并制定改进计划 |
| 1.0-3.9 | 需重视 | 严重问题，优先处理 |
