# 从会议内容生成评分问卷 — Prompt 设计说明

## 设计目标

将一段会议/培训的文字记录转化为高质量的评分问卷，题目必须与实际内容强相关，而非通用模板。

## 核心设计原则

### 1. 内容锚定（Content Anchoring）

题目必须引用实际讲过的内容。这是与通用问卷模板最大的区别。

```
通用模板：    "讲解是否清晰"（任何培训都能用）
内容锚定：    "讲师对飞书CLI安装过程的步骤说明是否让你能独立完成"（只有这场培训能用）
```

**为什么重要**：内容锚定的题目让被评者知道具体哪里好/哪里需要改进，而非只得到一个模糊的"还行"。

### 2. 先分析后生成（Analysis-First）

Prompt 要求 AI 先完成内容分析（识别主题、模块、知识点），再基于分析结果生成题目。这避免了 AI 直接套用训练数据中的通用问卷模板。

### 3. 正反例对比（Contrastive Examples）

Prompt 中同时给出"好的题目"和"差的题目"示例，让 AI 理解质量标准。这比只说"要具体"有效得多，因为"具体"的定义对 AI 来说是模糊的。

### 4. 会议类型感知（Context Awareness）

不同类型的会议需要不同的评估角度：

| 类型 | 评估重点 |
|------|---------|
| 培训教学 | 知识传递效果、动手操作指导、学员收获 |
| 经验分享 | 案例质量、可迁移性、启发程度 |
| 产品演示 | 功能理解度、使用意愿、对比现有方案 |
| 讨论会议 | 讨论深度、共识达成、后续行动明确性 |

### 5. 可操作性约束（Actionability Constraint）

每道题的低分结果必须能指向一个具体的改进方向。这通过题目的表述结构来实现：

```
可操作：  "安装环节的步骤说明是否让你能独立完成"
         → 低分意味着：步骤说明需要优化（具体改进方向）

不可操作："你觉得这场培训怎么样"
         → 低分意味着：不知道该改什么
```

## Prompt 结构

```
[角色设定] — 评估设计师身份
[工作流程] — 强制先分析后生成的思维链
[维度设计规则] — 从内容提取，非通用模板
[题目设计规则] — 具体性/可区分性/可操作性/中性
[正反例对比] — 好题目 vs 差题目
[输入] — 会议标题 + 文字记录
[输出格式] — 严格 JSON
```

## 输出质量检验标准

生成的题目应通过以下检验：

1. **唯一性测试**：这道题能否用于另一场完全不同的培训？如果能，说明不够具体
2. **改进指向测试**：如果某人打了3分，你能立刻知道该改什么吗？
3. **区分度测试**：同一维度内的2-4道题，是否测量了不同侧面？

## 降级策略

当 AI 分析不可用时（网络/API问题），系统降级为基于会议标题的通用模板。模板质量低于AI生成，但保证系统可用性。
